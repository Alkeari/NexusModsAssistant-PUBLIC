# Build Instructions for Reviewers

Nexus Mods Assistant, Alkeari Labs LLC.

## What is in this archive

Every git-tracked file needed to reproduce the build: TypeScript source under
`src/`, the two source manifests under `manifests/`, the build scripts under
`scripts/`, `webpack.config.js`, `tsconfig.json`, `package.json` and
`package-lock.json`. IDE state, captured reference pages and internal design
documents are excluded. `node_modules/` and all build output are excluded and are
regenerated by the commands below.

## Environment

- Built on Windows 11 Pro N, x64. The build is platform independent and has been
  run on Linux. There are no native dependencies and no platform specific build
  steps.
- Node.js v25.4.0, npm 11.9.0. Any Node 20 or newer works, including the Node
  24.14.0 on the AMO reviewer image (Ubuntu 24.04 LTS ARM64).
  Download: https://nodejs.org
- No other tooling is required. Every build tool is an open source npm package
  resolved from the public registry through `package-lock.json`. Nothing is
  web-based.

## Build

    npm ci
    npx cross-env BROWSER=firefox webpack --mode production

The reviewable output is `dist-firefox/`. That directory is the content of the
submitted package: `manifest.json` sits at the archive root and every other path
matches.

For the Chrome package the only difference is the manifest that gets copied:

    npx cross-env BROWSER=chrome webpack --mode production

which produces `dist-chrome/`.

## What the build does

`webpack.config.js` compiles three TypeScript entry points to three ES2020
bundles, and copies static assets unchanged:

| Entry point | Output |
|---|---|
| `src/background/background.ts` | `background/background.js` |
| `src/content/content.ts` | `content/content.js` |
| `src/popup/popup.ts` | `popup/popup.js` |

| Copied unchanged from | Copied to |
|---|---|
| `manifests/firefox.json` (or `manifests/chrome.json`) | `manifest.json` |
| `src/assets/icons/` | `icons/` |
| `src/popup/popup.html`, `src/popup/popup.css` | `popup/` |
| `src/content/content.css` | `content/` |

That is the whole build. There is no code generation, no post-processing step and
no network access during the build beyond `npm ci` resolving the locked
dependency tree.

## Notes for review

- Minification is enabled for release builds. `webpack.config.js` sets
  `optimization.minimize` to true whenever the mode is not `development`, so the
  emitted bundles are transpiled from TypeScript to ES2020, concatenated, and
  minified by webpack's default terser configuration. Running the build command
  above reproduces the submitted bundles byte for byte.
- No source maps are emitted. Production mode leaves webpack's `devtool` at
  `false`.
- No obfuscation of any kind is applied.
- No remote code is loaded or executed. There is no `eval`, no `new Function`,
  and no injected script tag anywhere in `src/`.
- `src/dev/reloader.ts` is in the archive and is not in the submitted build. It
  is a development convenience that reloads the unpacked extension from a local
  port, and `webpack.config.js` adds it to the entry list only when the mode is
  `development`. The production command above cannot include it. Search the
  emitted `background/background.js` for `NMA_DEV_RELOAD` to confirm.

## Data handling

The only data that leaves the browser is the user's own Nexus Mods Personal API
Key, which the user pastes into the extension popup or authorizes through Nexus
Mods Single Sign-On. It is stored in `chrome.storage.local` and sent only to
`https://api.nexusmods.com`, the service that issued it, to perform the
extension's single stated function. Nothing is transmitted to the developer or to
any third party. `store.steampowered.com`, `api.steampowered.com` and
`api.steamcmd.net` are contacted only to read public game version numbers, with
no user data attached.

The full accounting is in `PRIVACY-POLICY.md` in this archive.
